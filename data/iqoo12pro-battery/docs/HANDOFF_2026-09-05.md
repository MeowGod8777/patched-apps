Current verified semantics:

- private DB: `power8`
- table: `records`
- History timestamp = session start (`beginTime`)
- current sample interval = 3 s
- History first duration = valid screen-on sample count × 3 s
- History second duration = whole-session wall span (`endTime - beginTime`)
- History average power = `avg(current * voltage)` over valid screen-on discharge/not-charging samples

- per-app rows group by package + Scene mode; app duration = valid sample count × 3 s

The current-page capacity/status/voltage/temperature header is live GlobalStatus and must never be attached to an old History session.

## Screenshot production contract

Routine user behavior:

1. periodically capture recent Scene History, preferably with one overlap anchor
2. preserve timestamp + both History duration values
3. capture detail for new finalized sessions when exact screen-on, average power, theoretical runtime, or granular app attribution is needed
4. keep current/live screenshots provisional until matched to finalized History

Assistant behavior:

- parse
- apply History precision bounds
- dedupe using timestamp + power + durations + date/curve/app evidence, never watts alone
- append without rewriting old evidence
- retain granular future app rows when available
- update rolling statistics after enough new sessions accumulate

No routine OCR, CLEAR_TASK/force-stop automation, background Runner loop, or private-DB probing.

- Wi-Fi disconnected
- Data Available

