## Product goal

Build a low-interference, long-term natural-use battery ledger for iQOO 12 Pro / V2329A supporting reliable comparisons across:

- home Wi-Fi / mobile / mixed / other-Wi-Fi use when context evidence exists
- navigation vs non-navigation
- app/workload composition
- battery aging
- OriginOS / resolution / refresh / root / scheduler / other configuration changes

This is not a fixed-workload benchmark. Sessions do not need to be 100% -> 0%.

### Current storage/session semantics

Static RE established:

- private DB: `power8`
- table: `records`
- explicit `session` id per row
- `beginTime = min(time)` per session
- `endTime = max(time)` per session
- History timestamp formats **`beginTime`** -> History timestamp = **session start**
- current History/app sampling interval = **3 seconds**
- History first duration = valid screen-on sample count × 3 s
- History second duration = `endTime - beginTime` = whole-session wall span
- History second duration is not theoretical runtime
- session average power = `avg(current * voltage)` over valid screen-on discharge/not-charging samples
- theoretical runtime core ~= `batteryEnergy / abs(avgPower) × 0.9`
- current battery-energy helper nominal voltage = **3.86 V**, with the documented conditional doubled-energy branch

### History `x.xh` precision

Current formatter implements:

```text
shown_hours = floor(minutes / 6) / 10
```

Therefore both History duration values are **downward truncated in 6-minute / 0.1h buckets**, not rounded.

For displayed `D h`:

```text
D h <= actual duration < D + 0.1 h
```

History start timestamp is minute-resolution UI output. An end inferred from History-only evidence must be represented as bounds rather than a false exact timestamp.

## Current per-app row semantics

Current Scene 9.3.8 per-app query groups by:

```text
package + Scene mode
```

It uses valid screen-on discharge/not-charging rows and app duration is:

```text
count(current) × 3 seconds
```

Therefore future granular app evidence must preserve `mode`; two rows for the same package under different modes are not automatically merged.

Target future app-row semantics:

```text
duration_semantics = scene_valid_app_samples_3s
```

The historical 436 deduplicated per-app rows were not retained as a granular repository artifact, and referenced `sync_raw/detail-*` files are absent from the repo tree. **Do not reconstruct historical `app_sessions.csv` from `app_summary.csv`.**

## Production screenshot contract

See `SCREENSHOT_INGESTION_V1.md`.

Routine behavior:

1. periodically capture recent History rows, preferably with one known overlap row
2. preserve timestamp + both History duration values
3. capture detail for new finalized sessions when exact screen-on, average power, theoretical runtime, or granular app attribution is needed
4. keep current/live screenshots provisional until reconciled with finalized History
5. dedupe using timestamp + power + durations + date/curve/app evidence, never watts alone
6. append new sessions without rewriting old evidence

No routine UIAutomator, OCR, force-stop/CLEAR_TASK, background Runner, or private-DB probe.
