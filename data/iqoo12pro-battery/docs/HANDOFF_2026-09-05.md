## Product goal

Build a low-interference, long-term natural-usage battery ledger for iQOO 12 Pro / V2329A that can support reliable comparisons across:

- home Wi-Fi vs out-of-home mobile use
- mixed sessions
- navigation vs non-navigation
- app/workload composition
- battery aging
- OriginOS / resolution / refresh / root / scheduler / other configuration changes

This is not a fixed workload benchmark and sessions do not need to be 100% -> 0%.

## Important corrections already established

1. The 2026-09-05 3.38 W -> 3.23 W -> 3.01 W observations were intermediate snapshots of one live session, not separate finalized sessions.
2. Scene ActivityPowerUtilization battery capacity/status/voltage/temperature header values come from current `GlobalStatus`; they are not old History-session metadata.
3. Exact detail `screen_on_duration`, not rounded History `0.5h` style text, controls eligibility.
4. Average W alone is never a dedupe key.
5. Old all-`Scene`/unresolved raw evidence remains immutable but is not canonical when superseded by healthy capture.

## What was learned from the failed automation effort

- UIAutomator can retrieve Scene detail data but repeated long runs destabilize Scene.
- App labels can remain at default `Scene` while async label loading is incomplete.
- In more severe failures Scene's main dashboard loses CPU/GPU/memory/uptime data; reopening Scene often restores the backend/session.
- Backlog drainer scripts are useful only as one-time forensic recovery tools.
- Do not create another routine UIAutomator version.

## Current device-side context collection

MacroDroid currently writes:

`/sdcard/SceneBattery/network_timeline_md.csv`

Pilot events are only:

- home SSID connected -> `home_wifi`
- all home SSIDs absent for 30 s -> `out_4g`

This pilot logic must not be treated as final because `not home Wi-Fi != mobile`. Final target context states are:

- `home_wifi`
- `mobile`
- `other_wifi`
- `unknown`

A coverage/heartbeat event should also be designed so missing MacroDroid execution is distinguishable from a stable unchanged state.

Navigation automation is not implemented yet and should wait until the base context model is stable.

`app_summary.csv` is derived. The canonical app layer must retain per-session rows.

## Key unresolved semantic issue

To intersect a Scene session with MacroDroid context, the session's true wall-clock interval must be known.

Scene History displays two duration-like values (for example `1.4h / 2.5h`). Exact detail gives `screen_on_duration`, but the second History value and History timestamp start/end semantics have not been formally verified.

Do not derive `interval_start`/`interval_end` until this is verified from source/DB/controlled observation.
